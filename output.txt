# Hermes G2 Media Controller — Architecture Blueprint

---

## Critical Analysis

### Input Conflict: Mode Entry/Exit

The `isEventCapture: 1` flag in the container already claims gestures while the plugin is focused. The real problem is **re-entry**: if the user navigates away to another G2 app and back, capture resumes with no mode indicator. Three strategies ranked by UX cost:

1. **Auto-timeout lock** (recommended): if no gesture occurs within a configurable idle window (e.g., 30s), the plugin transitions from "intercept mode" to "passive display mode" — it still shows the HUD but passes gestures through. A brief `[ CTRL OFF ]` toast signals the transition. Re-engaging requires a single tap while the passive HUD is visible.
2. **Triple-tap toggle**: The SDK exposes `CLICK_EVENT` and `DOUBLE_CLICK_EVENT`. Triple-tap is not a native event type, but you can implement it in software by counting single taps within a 400ms window and suppressing the action until the window closes. Adds ~400ms latency to all single taps — acceptable for media but annoying.
3. **Long-press exit**: Map long-press to "toggle intercept mode" instead of mute, and add a separate volume-long-press combo for mute. Cleanest dedicated exit with no latency tradeoff.

**Recommended**: option 1 + option 3 together. The auto-timeout handles the common "walk away" case; long press gives a deliberate exit.

---

### Battery & Network Polling Efficiency

Do not poll at a fixed interval. Use a purely event-driven model:

- **Phone battery**: Register `BatteryManager.ACTION_BATTERY_CHANGED` once as a sticky broadcast. Android only fires this when level actually changes (typically 1% increments). Zero polling overhead.
- **Network state**: `ConnectivityManager.registerNetworkCallback()` fires on transitions only. Don't call `getActiveNetwork()` on a timer.
- **Glasses battery**: The Even Hub SDK fires an event when battery state changes — subscribe via `onEvenHubEvent` and check for a battery event type rather than polling the BLE characteristic.
- **Coalescing**: Batch all three state fields into one outbound packet and debounce updates with a 500ms window. Three rapid state changes (network drop + reconnect + battery tick) send a single payload instead of three.
- **Send trigger**: Only push to the HUD on actual delta — compare new state against last-sent state before transmitting.

Result: BLE airtime for status is measured in packets per hour, not per minute.

---

### Connection State Triggers

The G2 plugin side detects loss passively: when `fetch()` to the phone HTTP server fails (or times out), the plugin knows the bridge is down. It should:
1. Immediately render `[ ! ] Bridge Offline` in the HUD container
2. Enter an exponential-backoff retry loop (1s → 2s → 4s → 8s → cap at 30s)
3. On successful reconnect, restore the last known media state and display `[ ✓ ] Reconnected` for 2s

On the Android side, if this is HTTP (not raw BLE GATT), there's no connection state to manage — the server just restarts if it crashes. If you ever move to raw BLE GATT, use `BluetoothGatt.connect(device, autoConnect = true)` and implement `onConnectionStateChange` with the same backoff pattern.

### Network State Serialization (1-byte encoding)

```
Bit layout of a single byte:
  [7..4] = type  [3..0] = signal strength (0–15, optional, set to 0 if unused)

0x00  Offline / No connectivity
0x10  Wi-Fi (any strength)
0x20  LTE / 4G
0x30  5G (NR)
0x40  3G / HSPA
0x50  2G / EDGE
0x60  Ethernet (tablet/dock mode)
0x7F  Unknown
```

Upper nibble = connection type (6 useful states, 10 reserved for future). Lower nibble = RSSI bucket if you ever want signal bars. For now zero-fill it. The entire battery+network+volume status fits in 3 bytes: `[phone_battery_0–100][glasses_battery_0–100][network_byte]`.

## Architecture Blueprint

The cleanest approach **extends the existing HTTP polling pattern** rather than introducing raw BLE GATT from scratch. The G2 plugin already polls an HTTP endpoint; adding POST routes for gesture commands keeps the architecture uniform and avoids Android BLE GATT server complexity.

```
G2 Plugin (TypeScript)          Phone Companion (Android/Kotlin)
┌─────────────────────┐         ┌──────────────────────────────┐
│  Gesture Intercept  │──POST──▶│  /media/command              │
│  HUD Renderer       │◀─GET───│  /media/status               │
│  Poll loop (3s)     │         │  MediaSessionManager         │
└─────────────────────┘         │  BatteryManager broadcast    │
                                 │  ConnectivityManager callback│
                                 └──────────────────────────────┘
```

## Edge Case Handling

### Multiple Active Media Apps

`getActiveSessions()` returns controllers sorted by recency. The service picks `firstOrNull { it.playbackState != null }` — the most recently active app with a non-null playback state wins. When a phone call starts, `AudioManager.AudioFocusRequest` will duck/suspend music; the MediaSession state transitions to `STATE_PAUSED`, which the callback catches immediately and pushes to the HUD as `[ ‖ ] Paused`.

### Phone Call Interception

Register a `TelephonyCallback` (API 31+) or `PhoneStateListener` (legacy). On RINGING or OFFHOOK state, set `inCall = true` in MediaState. The G2 plugin checks `inCall` in the status response and renders `[ ☎ ] On Call` instead of track info, suppressing all media commands while `inCall` is true to avoid accidentally ending a call.

### Volume Clamping

`ADJUST_RAISE` on Android clamps at max volume silently. No special handling needed, but echo the actual post-adjustment volume back in the next `/media/status` poll so the HUD reflects reality rather than assuming the adjustment succeeded.

## API Contract

### GET /media/status

Response (JSON):
```json
{
  "playing":   true,
  "buffering": false,
  "track":     "Song Title",
  "artist":    "Artist Name",
  "volume":    70,
  "phoneBat":  84,
  "netByte":   32,
  "inCall":    false
}
```

`netByte` values: `0x00` = Offline, `0x10` = Wi-Fi, `0x20` = LTE, `0x30` = 5G, `0x40` = 3G, `0x50` = Edge.

### POST /media/command

Request body (JSON):
```json
{ "cmd": "play_pause" }
```

Valid `cmd` values: `play_pause`, `next`, `vol_up`, `vol_down`, `mute_toggle`.

Response:
```json
{ "ok": true }
```
